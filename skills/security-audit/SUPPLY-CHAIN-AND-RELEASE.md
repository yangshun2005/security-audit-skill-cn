# 供应链与发布漏洞挖掘

#### 何时使用本文件

当目标涉及解析依赖、从不受信任的贡献构建、运行 CI、创建发布构建产物、签名或晋升构建、加载插件，或更新已部署软件时，使用本文件。本领域覆盖从源代码和依赖到用户运行的构建产物的信任交接。本地二进制加载器内部的缺陷请使用 `MEMORY-SAFETY-AND-BINARY.md`，运行时工作负载权限请使用 `CLOUD-AND-DEPLOYMENT.md`。

将大型目标拆分为依赖解析、CI 隔离、构建产物来源、发布授权和更新器/插件信任。

## 核心纪律（纳入本领域每个 agent 提示词）

```
- 可变或已知存在漏洞的依赖本身不构成发现。需说明谁能影响解析、哪个构建消费它，以及由此产生的执行或发布边界。
- 追踪每个交接环节的完整性：源身份、解析后的输入、构建 worker、构建产物身份、测试结果、签名/证明、晋升和更新消费者。
- CI 配置即授权代码。确定哪个事件触发了工作流、运行谁的代码、存在哪些密钥和令牌，以及它可以发布或变更什么。
- 从与构建产物相同的不可信位置获取的校验和不能建立独立完整性。识别可信根和失败行为。
- 对于仓库内控制流失败且有界本地验证的，使用 `confirmed`。对于分支保护、托管 runner、镜像仓库、签名服务或生产晋升等不可观测的事实，使用 `needs_validation`。
```

## 依赖与构建输入攻击类别（subagent_type: `general`）

**依赖源与命名空间混淆**
解析器配置可能选择非预期的公共/私有命名空间、回退镜像仓库、镜像、仓库或源 URL。审查包名、源优先级、锁文件和校验和使用、备用构建文件、平台特定解析，以及首次安装与更新行为。

**可变与未绑定的构建输入**
构建消费分支、标签、未验证的子模块、下载的工具、生成的资源、远程包含、浮动 CI action 或容器标签，其内容可在未经源码审查的情况下变更。需要存在低信任写入者和通往可信构建产物的路径；可复现性本身不能证明真实性。

**生成源与代码生成来源缺口**
Schema、vendored 归档、生成的客户端、本地化、文档示例或二进制 blob 产生可执行或随附内容，却未经过与源码相同的审查和完整性门禁。比较本地重新生成与已提交输出，并验证谁控制输入和生成器。

**构建上下文包含**
密钥、本地配置、仓库元数据、测试夹具或开发者产物因构建上下文和忽略规则超出预期发布输入而进入包或镜像。确认最终构建产物暴露了真实凭据、私有数据或特权配置。

## CI 与自动化攻击类别（subagent_type: `general`）

**特权工作流中的不可信代码**
Pull Request、Issue 评论、Fork、依赖更新或外部事件以受保护密钥、写令牌、部署权限或可信 runner 运行贡献者控制的代码。比较触发类型、检出 ref、审批门禁、环境保护和权限收窄。不要假设源码中不存在的仓库托管默认值。

**工作流命令与表达式混淆**
攻击者控制的分支名、提交信息、Issue 字段、构建产物名、矩阵值或生成输出未经规范化验证即进入 shell 命令、模板表达式、路径或特权工作流输入。

**缓存、构建产物与工作区信任混用**
低信任任务可填充缓存、构建产物、共享工作区或输出，随后高信任任务恢复并执行或发布。审查缓存键和命名空间、构建产物生产者身份、摘要绑定、保留策略，以及晋升是否按可变名称重新解析。

**自动化身份越权**
CI 任务获得的权限超出操作、仓库、环境或时长所需，且不可信任务输入可选择受影响的资源。仅缺少最小权限属于加固；需要存在可达的特权操作。

## 发布与更新攻击类别（subagent_type: `general`）

**构建到晋升的替换**
测试、审查、签名和发布引用可变标签、文件名、通道或构建产物 ID，而非同一不可变摘要。检查构建与发布之间的每次复制、重新打包、架构合并和来源步骤。

**发布授权与签名策略缺口**
发布或签名从错误的工作流、仓库、分支、环境、密钥角色或阈值被接受。审查证明中的身份声明，并验证消费者对其进行了校验，而不仅仅是签名有效。轮换、过期和吊销必须在策略要求处失败关闭。

**更新元数据与回滚混淆**
更新器认证载荷字节但不认证版本、产品、平台、通道、目标路径、过期或回滚状态，或从不同授权事务接受元数据和载荷。验证原子安装和恢复行为。无策略绑定的签名 API 调用是不完整的。

**插件与扩展信任扩张**
扩展包获得超出其声明范围的主机权限，低信任发布者可替换另一发布者的身份，或安装/更新 Hook 在真实性和能力检查之前运行。有意安装任意同用户插件不构成权限边界。

## 通用方法（适用于上述所有类别）

- 从已发布摘要或已安装更新向后追溯至每个源、生成输入、凭据、worker、缓存、测试结果和授权决策。
- 并排比较不可信与受保护的工作流事件。标记它们之间每个持久化通道穿越，并要求不可变身份加生产者信任。
- 审查已吊销密钥、下载失败、缺失证明、部分平台发布、回滚和镜像仓库中断路径。失败策略是发布完整性的一部分。

## 验证规则（在此报告任何发现之前应用）

1. 指明低信任行为者、可控的源/缓存/构建产物/元数据、消费的可信任务或更新器，以及由此产生的未授权发布、代码包含、密钥泄露或特权执行。
2. 证明跨断裂交接的构建产物身份。不同的可变名称或未绑定摘要必须到达真实消费者。
3. 验证固定版本的内置包管理器、仓库托管、镜像仓库和签名默认值。未知的托管控制项需要 `needs_validation`。
4. 保持本地验证有界：使用无害的夹具仓库、虚拟凭据标记、本地镜像仓库/配置和非生产构建产物命名空间。不要发布或更改真实发布版本。
5. 仅在源码可见的完整交接和有意义结果下返回 `confirmed`。返回 `needs_validation` 时需附带所有者必须观察的精确分支、runner、镜像仓库、签名或部署事实。
