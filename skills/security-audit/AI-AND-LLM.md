# AI、LLM 与 Agent 狩猎

#### 何时使用本文件

当语言模型参与信任敏感决策时使用本文件：聊天机器人与助手、RAG 流水线、持久化 Agent 记忆、Agent/工具调用循环、MCP 服务端与客户端、从不可信输入构建提示词的代码，或消费模型输出并据此行动的代码。关键数据流是*不可信内容 → 模型或记忆 → 能力、权限或汇聚点*。

本文件与 `ATTACK-CLASSES.md` 配合使用，而非替代它。传输、访问控制、查询构建、文件系统使用和输出渲染仍是普通信任边界。本文件覆盖模型特有的委托层。大型目标按检索、记忆、工具分发、MCP 和输出处理拆分。

## 核心纪律（本领域每个 Agent 提示词都必须包含）

```
- 仅提示词注入不构成发现。必须存在代码级边界失效：内容到达另一主体的上下文、调用请求者不具备的权限、泄露其无法读取的数据，或驱动其无法直接触达的汇聚点。
- 模型输出、记忆、工具描述和 MCP 响应均为不可信输入。指出授予权限、信任输出、写入持久状态或送入汇聚点的代码。
- 护栏提示词不是安全边界。只计入确定性检查、资源范围授权、隔离、绑定和受限凭据。
- 说明攻击者、受影响主体、实际执行身份、资源、确切操作、所用权限和可观察影响。请求者有意直接使用其现有权限的请求，不因由模型执行而成为委托缺陷。
- 授权与操作绑定是独立控制。攻击者控制的内容在受影响主体的有效权限下引发操作，而该主体并未有意请求或批准该确切操作，即为操作绑定失效。
- 仅在源码证据和有界本地验证确立边界与结果后，才将候选分类为 `confirmed`。当所需提供方、部署、模型、渲染器或身份行为无法在本地观察时，使用 `needs_validation`。
```

## 上下文、检索与记忆攻击类（subagent_type: `general`）

**通过检索或摄取内容的间接注入**
攻击者可写入 RAG 文档、索引页面、文件、邮件、Issue 正文、工具响应或元数据，使其进入另一主体的模型上下文。追踪每个来源的写入者、检索如何限定范围、哪个会话消费它，以及该处启用了什么能力。分别检查隔离、资源授权和与消费主体意图的绑定。缺陷在于缺少确定性控制，而非文本本身具有说服力。

**跨会话或跨租户上下文泄漏**
对话历史、嵌入、检索结果或提示词缓存的键范围过宽。在查询本身和每个缓存键中验证租户与 ACL 过滤。对象上存储租户字段，若替代查询、共享缓存或批处理路径省略该字段，则不构成强制执行。

**持久化记忆投毒**
攻击者控制的内容或模型摘要被写入记忆，随后影响另一任务、用户或特权会话。审查谁可创建、更新、合并和删除记忆；其来源与租户范围；低信任观察是否变为持久指令或事实；以及检索是否区分用户偏好与工具策略。用户有意保存且仅用于该用户有意、允许请求的记忆，不构成跨边界发现。

**提示词角色与来源混淆**
提示词组装让不可信文本冒充系统消息、先前轮次、工具结果、策略或记忆记录。查找字符串拼接、无类型历史、调用方控制的角色字段，以及丢失来源标签的序列化往返。确认伪造来源改变了确定性信任决策或触达有意义的能力。

## 工具与操作攻击类（subagent_type: `general`）

**工具参数注入下游汇聚点**
模型生成的参数未经处理器侧验证即到达 SQL、Shell、文件、URL 获取或特权 API。将工具 Schema 视为输入解析，然后沿每个字段从解码调用追踪到汇聚点。结构化输出缩小形状，但不确立授权、安全路径、安全 URL 或查询语义。

**过度代理与混淆代理权限**
Agent 使用服务身份或宽泛凭据，而工具处理器未重新检查请求主体对指定资源的权限。验证实际身份，以及调用方能否通过正常产品界面执行该确切操作。共享凭据但强制按用户查询范围，不构成缺陷。

**操作确认与批准绑定**
用户批准一个已描述的操作，但执行可使用变更的参数、不同资源、不同主体或后续模型轮次。当攻击者控制的内容在受害者有效权限下引发副作用，而受害者并未有意请求或批准时，即使通用授权允许受害者执行该操作，也存在操作绑定缺陷。审查意图或确认是否绑定规范化工具名、完整参数对象、请求者、目标、金额、过期时间和批次成员资格。检查重试和恢复会话：批准不得授权变更或重复的副作用。

**工具 Schema 与分发器不一致**
Schema 接受别名、额外字段、重复键、强制转换、嵌套自由格式对象或越界值，而分发器或处理器解释不同。比较 Schema 验证、规范化、生成的绑定和处理器默认值。在值成为资源选择器或安全相关选项处再次验证。

**无界委托操作循环**
有界请求可排队重复消费、发送、变更或外部 API 工作，而无每请求预算、每操作授权、取消或幂等控制。确认对共享成本、配额、其他用户或持久状态的影响。不要通过耗尽服务来测试；使用代码级核算和有界本地循环。

## MCP 与子 Agent 信任类（subagent_type: `general`）

**子 Agent 与 MCP 信任继承**
委托任务获得完整会话、凭据、记忆或能力，而非所需最小权限。检查每次调用携带的主体和租户、能力收窄、凭据受众，以及委托结果返回时是否被视为不可信。

**MCP 服务端与工具身份混淆**
调用或结果按攻击者可影响的服务器名、工具名、请求 ID、资源 URI 或模型选择的别名路由，而非按已认证连接和未完成请求路由。检查两个服务器能否声称相同工具或资源身份、重连是否改变绑定，以及一个服务器的响应能否满足另一服务器的待处理调用。

**MCP 元数据与 Schema 作为策略**
MCP 对等方提供的工具描述、资源元数据、提示词、补全提示或 Schema 被信任为策略或授权。这些字段可引导模型，但不能授予能力。找出元数据冲突时仍具权威性的确定性允许列表、服务器身份检查和处理器授权。

## 输出与泄露攻击类（subagent_type: `general`）

**不安全的输出渲染**
模型输出到达执行的 HTML、Markdown、模板、URL 或命令汇聚点，而未满足该汇聚点所需的编码和策略。对于浏览器渲染，在 `CLIENT-SIDE.md` 中验证自动加载资源和 CSP 或净化；仓库外的渲染器行为使候选为 `needs_validation`。

**敏感上下文提取**
组装上下文包含凭据、另一用户数据、私有源码或本身授予访问的策略值，且用户影响的输出暴露它们。阅读提示词组装和数据获取代码。泄露不跨越数据边界的通用指令或行为不构成发现。

## 通用方法（适用于以上所有）

- 先绘制四张图：每个执行身份、每项能力、每个可写上下文或记忆来源、每个输出目的地。然后将起点的主体连接到终点的权限。
- 从有副作用的工具开始，逆向追踪分发器、Schema、确认、模型上下文、检索和摄取。从持久记忆读取开始，追踪每个写入者。
- 对同一操作比较直接、排队、重试、恢复、批处理和委托路径。最强门控必须在参数最终确定之后、每个副作用之前生效。

## 验证规则（在此报告任何发现前应用）

1. 命名跨越的边界和可观察结果：攻击者、受影响主体或共享资源、执行身份、目标，以及未授权或未请求的操作或泄露。
2. 对于混淆代理权限主张，证明工具缺少请求者与资源授权，且攻击者无法正常执行相同操作。对于操作绑定主张，改为证明攻击者控制的内容在受影响主体权限下引发了该主体未有意请求或批准的操作。有效的通用授权不确立该意图。
3. 对于记忆或检索主张，同时引用攻击者控制的写入和后续跨主体读取或特权决策。仅有共享记录而无可达消费者不足够。
4. 对于操作绑定，确立有意请求或规范化批准对象（如有），并与处理器使用的对象比较。确认本地可观察的未请求操作、变更、重复或权限变更，而不将测试扩展到有害执行。对于 Schema 不一致，比较规范化验证对象与处理器对象。
5. 对于 MCP 身份主张，验证已认证连接、请求关联、工具命名空间和实际凭据。若需要外部服务器身份或部署路由，标记 `needs_validation`。
6. 仅以完整源码追踪和有意义结果返回 `confirmed` 发现。对于特定未解决边界事实返回 `needs_validation`，并说明解决它所需的有界本地或所有者观察检查。
