# 内存安全、二进制与内核漏洞挖掘

#### 何时使用本文件

当目标在不安全内存或特权上下文中处理不可信字节时使用本文件：C/C++/Objective-C、Rust `unsafe`、FFI、内核模块与驱动、解析器与解码器、网络守护进程、固件、二进制加载器、语言运行时和 JIT。协议授权与状态机逻辑请使用 `PROTOCOLS-RPC-AND-MESSAGING.md`；本文件聚焦进程完整性、内存安全、ABI 边界和加载器行为。

从第 1 阶段选取相关类别，并按解析器、分配器/生命周期、FFI、并发、加载器、运行时或特权接口拆分大型目标。

## 核心纪律（本领域每个 agent 提示词都必须包含）

```
- 从攻击者可控输入和所有调用方重新推导每个边界和生命周期。按最坏可接受情况验证，而非典型测试向量。
- panic、sanitizer 发现或崩溃只有在真实不可信输入触达时才证明缺陷。不要仅凭标签推断内存破坏、代码执行或共享可用性影响。
- 在本地 harness 中用 sanitizer、确定性并发测试、现有 fuzz 目标和调试器辅助的故障分类进行验证。证明被违反的不变量和可观测影响后即停止；不要开发破坏后利用技术。
- 汇编、JIT 代码、自定义分配器、对象内访问和外部库可能逃逸 sanitizer 覆盖。确认哪些相关指令被插桩。
- 只有源码证据和有界本地验证确立缺陷与影响后，才归类为 `confirmed`。当 ABI、分配器、架构、特性、部署或可达性事实仍未知时，使用 `needs_validation`。
```

## 边界、整数与表示攻击类别（subagent_type: `general`）

**越界读或写**
长度、偏移、索引或终止符在未正确限界的情况下到达固定或已分配缓冲区。在考虑前缀、对齐、填充和终止符后重新计算可用余量。检查源和目标容量，以及短输入是否在其声明长度被信任之前就被读取。

**整数溢出、下溢、截断与符号性**
审查分配、复制、循环、索引和指针操作之前的攻击者可控算术。高命中模式包括 `b > a` 时的 `a - b`、`count * element_size`、接近类型最大值的加法、负值转为无符号、64 位长度收窄为 32 位字段，以及 `-1` 等哨兵值变成大尺寸。确认后续使用的是哪种受检表示。

**单位与指针深度混淆**
代码混用字节、元素、代码单元、页、字、线缆单位和嵌套指针元素大小。在解析、验证、分配、API 边界和复制处比较单位。使用与分配相同的错误单位做边界检查仍然是错的。

**未初始化或部分初始化数据**
缓冲区、填充、结构体字段或向量容量在初始化前被返回、比较、哈希、序列化或跨信任边界传递。需要可观测的消费者和真实输出长度；仅栈分配本身不构成泄露。

## 生命周期、类型与并发攻击类别（subagent_type: `general`）

**释放后使用、过期视图与双重释放**
所有者被释放时，回调、等待队列、定时器、迭代器、借用切片或缓存的裸指针仍可能使用它们。审查每条错误、取消、关闭和重分配路径。对于嵌入式通知锚点，每条释放路径必须排空或分离所有观察者。

**类型混淆与非法向下转型**
标签、vtable、联合体判别符、对象种类或外部句柄的检查方式与后续读取的表示不同。查找未检查的动态转换、重用后的过期标签，以及已验证元素与被消费元素不同的序列化类型。在本地确认错误类型的读或写，不将测试扩展到被违反的不变量之外。

**引用计数与所有权竞争**
非原子 retain/release、检查后未加锁使用，或跨线程所有权不一致，可能在访问期间释放或修改对象。比较同一锁和所有权规则下的快速、错误、关闭和兼容路径。

**共享状态竞争与 TOCTOU**
并发解析器流、全局缓存、惰性初始化、信号处理器和资源拆除可能使先前建立的边界、策略或指针失效。用可重复的本地调度、屏障或线程 sanitizer 验证竞争；没有安全相关状态转换的假设性交错仍为 `needs_validation`。

**锁顺序、死锁与饥饿**
外部可达操作以不一致顺序获取锁，或在回调和阻塞 I/O 期间持有锁。仅当有界输入能停止共享进展时才在可用性下报告；否则作为并发缺陷记录待修。

## FFI 与 ABI 攻击类别（subagent_type: `general`）

**指针-长度与所有权契约不匹配**
调用方与被调用方对谁分配、释放、固定或修改缓冲区、指针有效多久，或长度是字节还是元素存在分歧。追踪每个 `extern`、CGo/JNI/Python/原生绑定和生成包装器的两侧。检查 null、零长度、别名和回调保留。

**布局、对齐与枚举不一致**
外部代码收到的结构体、位域、紧凑记录、回调签名、整数宽度、枚举或调用约定因架构或构建标志而异。验证 `repr`、打包、对齐、字节序和 ABI 特定类型。仓库内声明不匹配可在本地确认；不透明外部实现需要 `needs_validation`。

**展开、异常与线程亲和性违规**
异常或 panic 跨越禁止展开的 ABI，回调在拆除后运行，或要求单一运行时线程的 API 在其他地方被调用。审查错误转换和取消。在分配影响前确认进程是中止还是状态被破坏。

## 二进制加载与运行时攻击类别（subagent_type: `general`）

**库、插件与可执行文件搜索顺序信任**
特权进程从较低信任主体可写的路径加载库、插件、运行时镜像或辅助程序，或通过攻击者可影响的工作目录或环境解析裸名称。比较预期安装所有权与每条回退和兼容搜索路径。用户将自有插件加载到自有进程不构成边界违规。

**缺失构建产物身份或签名绑定**
加载器验证一个文件或元数据记录，但因路径解析、文件替换、架构切片或嵌入资源未绑定到检查而映射了不同镜像。供应链渠道真实性属于 `SUPPLY-CHAIN-AND-RELEASE.md`；本类别覆盖本地验证到映射之间的缺口。

**畸形二进制元数据与重定位处理**
偏移、计数、节、重定位、符号、字节码或调试元数据在范围、重叠和表示检查之前被信任。用有界本地夹具和 sanitizer 测试解析器。区分内存破坏与安全拒绝的畸形文件。

**JIT 与生成代码一致性**
验证器、解释器、优化器和生成代码对类型、边界、副作用或生命周期存在分歧。用同一本地输入对比优化与未优化路径。确认进程完整性影响；停留在语言语义内的输出差异不是发现。

**卸载、重载与拆除安全**
活跃函数指针、回调、工作线程或数据视图在模块卸载或运行时重置后存活。像审查启动一样仔细审查关闭和加载失败清理。

## 内核与特权接口攻击类别（subagent_type: `general`）

**用户复制边界与重复读取**
系统调用、ioctl、驱动或内核解析器从用户内存推导可信事实，然后再次读取同一可变地址。一次性复制完整请求或重新验证后续复制。同时审计每个用户复制原语的大小、方向和访问检查。

**特权对象生命周期与分派一致性**
外部可达对象存在不平衡的 retain/release、未排空观察者的拆除、未检查的选择器/表索引，或省略守卫的重复兼容路径。并排对比每条分派和释放路径。

**权限不足的强大接口**
设备节点、管理套接字、辅助程序或管理 API 验证形状但不验证调用方对资源的权限。确立实际接口所有权和可达性；仓库外的权限或沙箱策略使其成为 `needs_validation`。

## 通用手法（适用于以上所有类别）

- 审计修复和重复路径中相同的源到汇形状。一个调用方、架构、协议角色、特性标志或兼容路径中的检查不保护其兄弟路径。
- 为每个解析器或 FFI 边界建表：接受的长度/类型、受检表示、分配所有者、消费者、线程和拆除。大多数原生发现是该表中的一处不一致。
- 使用现有语料库和小型本地生成的边界夹具。保存精确的 sanitizer/运行时输出和触发它的输入属性；避免大量资源消耗和任何实时目标。

## 验证规则（在此报告任何发现之前适用）

1. 确立真实的不可信入口和违反边界、类型、生命周期、ABI、并发、加载器或权限不变量的确切操作。
2. 分类可观测影响：非法读、非法写、过期别名、错误对象、未初始化输出、未授权镜像加载、死锁或安全进程终止。不要声称比观察到的更强影响。
3. 运行复现影响所需的最窄本地 harness、现有测试、sanitizer 或 fuzzer。验证 sanitizer 对故障操作的覆盖并记录架构/构建条件。
4. 对于并发，使用确定性调度或 sanitizer 跟踪。对于二进制加载，证明受检身份与映射身份不同，并指出较低信任的写入者。
5. 仅凭精确输入、源码追踪和观察结果返回 `confirmed` 发现。对于具体未解决的可达性、ABI、构建、部署或运行时事实返回 `needs_validation`，并说明所需的有界检查。
