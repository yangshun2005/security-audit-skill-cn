# 云与部署狩猎

#### 何时使用本文件

当仓库定义了云身份、基础设施、容器、Kubernetes、服务网格、无服务器函数、边缘 worker、入口、对象存储、托管服务或环境特定配置时，使用本文件。本领域考察已部署组件是否获得预期的身份、隔离、网络可达性、密钥和策略。源码通常表达意图而非实际事实，因此需将源码确认的缺陷与部署验证需求分开。

构建与晋升信任使用 `SUPPLY-CHAIN-AND-RELEASE.md`，HTTP 代理语义使用 `WEB-PROTOCOL-AND-AUTH.md`，数据存储租户范围使用 `DATA-ISOLATION-AND-LIFECYCLE.md`。

## 核心纪律（纳入本领域每个 agent 提示词）

```
- 不要仅凭清单推断实际暴露。确认哪个环境消费它、哪些默认值或覆盖层修改了它、源码路径是否生效。
- 将每个工作负载的身份映射到具体操作和资源。仅当低信任输入能触达未授权操作时，宽泛策略才算发现。
- 入口、代理、服务网格、元数据服务和准入策略是真实边界，但只有配置和挂载可见时才能计入控制。
- 密钥引用不等于密钥泄露。需要低信任读取者、输出、构建产物、日志路径或不安全回退。
- 活跃的仓库内配置和本地渲染/策略验证使用 `confirmed`。账户策略、网络挂载、运行时准入、托管元数据或漂移需所有者观察，使用 `needs_validation`。
```

## 工作负载身份与 IAM 攻击类别（subagent_type: `general`）

**工作负载身份越权**
工作负载、Pod、函数、边缘 worker 或节点身份能对其角色之外的用户、账户、资源或 API 执行操作，且不可信请求或任务输入选择了该目标。审查云策略条件、资源模式、服务账户挂载、命名空间映射和回退凭据。

**跨账户或跨租户角色混淆**
角色代入、外部 ID、令牌交换、工作负载联合或资源策略接受未绑定到预期源账户、受众、仓库、命名空间或工作负载的身份声明。需同时确立信任策略和调用方控制的声明。

**应用授权委托给云元数据**
应用信任调用方提供的身份头、标签、标注、账户 ID 或资源元数据，未验证其来自云控制平面或可信代理。云 IAM 与应用授权是独立检查。

## 入口、网络与控制平面攻击类别（subagent_type: `general`）

**意外的服务或管理平面可达性**
入口、服务、监听器、安全组、负载均衡器注解、端口映射或服务器绑定将管理、调试、指标、节点、控制平面或内部 API 暴露给低信任网络。仅缺少网络控制属于 `needs_validation`；仓库控制的通往敏感处理器的公开路由可为 `confirmed`。

**可信代理与网格身份绕过**
后端接受来自预期入口/边车之外对等方的转发身份、mTLS 主体或授权元数据，或备用端口和健康/遗留路径绕过网格。验证头剥离、对等方可达性以及代理缺失时的 fail-open 行为。

**元数据与内部服务可达性**
不可信 URL、目标或协议选择携带工作负载凭据触达实例/容器元数据、控制平面套接字或内部 API。在 `ATTACK-CLASSES.md` 下追踪 URL 解析和重定向处理；此处确立已部署网络、元数据版本和身份边界。

## 容器与编排攻击类别（subagent_type: `general`）

**主机或控制平面能力暴露**
低信任工作负载能选择特权模式、能力、主机命名空间、主机路径、设备挂载、容器运行时套接字或服务账户令牌，跨越到节点/控制平面权限。仅缺少 seccomp 或只读文件系统属于加固问题，除非可达操作跨越该边界。

**准入与策略路径不一致**
一条部署路径强制执行镜像身份、命名空间、资源、密钥或特权策略，而另一控制器、任务、升级、恢复或兼容路径不执行。确认备用路径及最终部署对象。

**命名空间与标签信任混淆**
网络、准入、密钥或工作负载身份策略依赖低信任主体可设置的标签、注解、名称或命名空间。比较谁控制选择器与匹配授予何种权限。

## 配置与密钥生命周期攻击类别（subagent_type: `general`）

**安全控制优先级漂移**
开发值、chart 默认值、环境变量、命令行标志、功能门、边车注入或按区域覆盖层在已部署环境中禁用了认证、传输安全、租户范围或审计策略。为每个维护中的部署渲染最终配置，而非仅基础文件。

**跨工作负载边界的密钥暴露**
密钥进入日志、崩溃报告、进程参数、共享环境、宽泛卷、构建产物、服务发现或另一工作负载或租户可访问的读取 API。检查密钥类型和权限；公开端点或密钥 ID 不是凭据。

**凭据续期与故障回退**
工作负载凭据挂载、刷新、轮换或撤销失败，导致过期凭据保持活跃或应用接受低信任身份模式。审查启动、就绪、重连和缓存客户端行为。

## 托管存储、事件与边缘攻击类别（subagent_type: `general`）

**对象与签名 URL 策略混淆**
桶/容器策略、对象键、CDN 源或签名 URL 未能绑定主体、操作、对象命名空间、受众或过期时间。审查列表/版本操作和写入路径以及读取。

**事件源身份混淆**
函数或 worker 信任事件体字段作为源身份，未验证提供方签名信封、订阅/主题、账户、区域和重放状态。比较推送、拉取、重试和死信路径。

**边缘/运行时边界不匹配**
边缘或无服务器运行时假设的密钥、API、文件系统、隔离或租户策略与源运行时不同，回退到源会改变权限或缓存行为。确认哪个配置选择各路径。

## 通用动作（适用于以上所有）

- 渲染每个维护中的环境，制作外部端口、工作负载身份、网络对等方、挂载密钥和云资源的矩阵。差异需所有者或策略解释。
- 追踪低信任请求、对象、标签或事件进入云策略。展示哪个工作负载凭据执行最终操作，以及什么条件应限定其范围。
- 对比正常部署、迁移、恢复、节点维护、故障转移和本地/模拟器路径。审查网格、准入、身份、密钥或策略服务不可用时的行为。

## 验证规则（在此报告任何发现前应用）

1. 确立活跃源码路径和有效部署对象；否则使用 `needs_validation` 并说明缺少哪个渲染清单或所有者观察的挂载。
2. 指明低信任调用方/工作负载、云或应用身份、可控选择器、受影响资源以及未授权操作或泄露。
3. 在固定版本上验证提供方和编排器默认值。不要假设公网 IP、可达元数据服务、宽松防火墙或缺少准入挂载。
4. 本地验证可渲染模板、评估策略、在隔离夹具中检查容器/用户命名空间，或用虚拟身份运行模拟器。不要探测实际端点或修改共享云资源。
5. 仅在完整活跃源码追踪和具体边界结果下返回 `confirmed`。返回 `needs_validation` 时需附上所需的确切已部署策略、身份挂载、覆盖层、网络或漂移观察。
