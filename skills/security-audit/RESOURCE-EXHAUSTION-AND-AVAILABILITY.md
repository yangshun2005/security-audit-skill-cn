# 资源耗尽与可用性狩猎

#### 何时使用本文件

当不可信请求、消息、文件、租户状态或 agent 工作可能消耗 CPU、内存、磁盘、连接、worker 槽位、付费 API 或队列容量，或可能导致共享服务死锁/崩溃时，使用本文件。本领域区分可通过源码审查发现的可用性漏洞与一般性能问题。切勿通过压测共享或在线服务来验证。

内存完整性缺陷请使用 `MEMORY-SAFETY-AND-BINARY.md`，broker 投递逻辑请使用 `PROTOCOLS-RPC-AND-MESSAGING.md`。可触发的致命错误即使底层解析器在其他文件中覆盖，只要影响共享服务，也归入本文件。

## 核心纪律（本领域每个 agent 提示词都必须包含）

```
- 必须给出输入到成本的路径、缺失的有效边界，以及对其他用户、共享服务、安全功能或运营方付费的影响。请求方自身进程内的自限工作不构成服务漏洞。
- 仅有缺失的速率限制不够。在判定路径无界之前，检查请求体/消息/文件上限、并发、队列、截止时间、数据库约束、上游网关和按租户配额。
- 不要运行压测、饱和测试或生产测试。使用渐近分析、小边界夹具、模拟付费调用、严格本地资源限制和确定性取消测试。
- 说明攻击者成本、服务工作量、持久性、影响范围和恢复方式。一个有界输入产生超线性或持久共享效应，与持续大流量有本质区别。
- 源码可见的边界失效且已安全演示时使用 `confirmed`。上游上限、部署拓扑、自动扩缩容、付费配额或恢复行为不在仓库内时使用 `needs_validation`。
```

## 计算放大攻击类别（subagent_type: `general`）

**超线性解析、匹配或求值**
少量被接受的输入即可触发灾难性正则回溯、嵌套解析、递归校验、符号求值、图遍历、模板展开或对抗性排序/哈希行为。推导可接受的深度/基数与复杂度，然后在本地演示有界增长曲线。

**解压缩与表示放大**
压缩、稀疏、嵌套、别名或编码输入在展开后远超已检查的传输或文件大小。在每次展开后以及跨解析器各阶段验证限制，包括归档、图片、字体、结构化文档和协议压缩表。

**数据库与下游查询放大**
小请求因查询深度、过滤基数、分页或展开字段未设边界，产生大范围扫描、病态连接、扇出、无界排序/聚合或大量下游调用。确认授权并非有意允许相同资源范围。

## 资源累积攻击类别（subagent_type: `general`）

**无界缓冲与基数**
请求体、乱序流、上传、会话、唯一缓存键、指标标签、日志字段、订阅或待处理任务在缺少单项和聚合限制时持续累积。检查断开、超时、取消和部分解析时的清理与过期。

**文件描述符、句柄与临时资源泄漏**
畸形或已取消的工作遗漏清理，保留 socket、文件、数据库游标、定时器、子进程、临时文件或对象引用。通过有界本地迭代确认泄漏可重复，且影响共享池。

**取消后的游离工作**
客户端超时、断开、任务取消或授权失败后控制权返回，但数据库、模型、网络或 worker 工作仍在运行。追踪取消和截止时间在每一层的传播。

## 配额与调度攻击类别（subagent_type: `general`）

**认证前工作失衡**
昂贵的解析、密钥查找、密码学运算、解压缩或外部请求发生在认证和最早的大小/速率门控之前。比较请求方最小投入与共享服务成本，并检查上游限制。

**配额核算范围与重置缺口**
核算使用攻击者可影响的 IP、路由、租户、密钥前缀、任务 ID 或其他维度，使某一主体的工作逃逸其预期预算或消耗另一主体的配额。审查整数溢出、分布式竞态、重试、重连和账户切换。

**Worker、池与优先级饥饿**
低优先级或攻击者控制的任务持有共享锁、worker、数据库池、事件循环轮次或调度器优先级，而无关用户需要这些资源。需给出绕过队列/并发公平性或超期仍占用槽位的路径。

## 故障与恢复攻击类别（subagent_type: `general`）

**可触发的致命错误或死锁**
不可信输入在共享进程中触发 `panic`、abort、致命断言、未处理异常、进程退出、锁循环或无限循环。确认监督者范围，以及是单个 worker 还是整个服务不可用。重启隔离 worker 可能降低影响，但不消除缺陷。

**重试风暴与失效开放放大**
超时、依赖错误、部分处理的消息或健康检查失败触发同步或无界重试，缺少抖动、上限、熔断或去重。验证单个有界故障源能产生持续聚合工作。

**毒记录与队头阻塞**
一条畸形记录或消息在共享队列、分区、启动扫描、迁移或恢复循环的前端反复失败。审查跳过/隔离策略、偏移量，以及其他租户是否共享被阻塞单元。

**不安全恢复与容量回滚**
重启、恢复、回退或清理路径重建无界状态、忽略当前配额，或恢复立即重复失败的输入。恢复正确性是可用性的一部分。

## 通用动作（适用于以上所有类别）

- 构建输入到资源表：最早接受的大小/基数、认证前工作、下游扇出、持久性、共享池、限制与清理归属、恢复。
- 比较聚合限制与单对象限制。一万个合法的一字节项可能绕过单消息上限，却耗尽租户级或进程级状态。
- 仅在严格 CPU/内存/时间限制和小增长点的隔离夹具中验证。模拟外部和付费调用，一旦缺失边界或取消可观察即停止。

## 验证规则（在此报告任何发现前适用）

1. 指明不可信输入、请求方工作量、服务放大或保留资源、共享爆炸半径和恢复方式。缺少限制但无具体共享影响属于加固建议。
2. 确认无源码可见的上游、解析器、队列、租户或框架边界阻止该路径。未知部署控制需标记 `needs_validation`。
3. 对超线性行为，确定可接受复杂度和有界本地增长。对泄漏，展示清理应发生后的可重复保留。对致命路径，识别进程/监督者隔离。
4. 按请求方低工作量、未认证可达性、跨租户范围、持久性和恢复差排序；不要用可用性影响来验证。
5. 仅在安全本地证明且共享效应有意义时返回 `confirmed`。返回 `needs_validation` 时须给出所有者必须检查的确切上游限制、拓扑、配额或恢复观察项。
