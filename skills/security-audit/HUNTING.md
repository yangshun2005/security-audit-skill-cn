# 漏洞狩猎

### 阶段 2：运行覆盖率驱动的狩猎波次

父代理将 `planned` 台账单元分配给 `general` 代理。使用足够多的专注狩猎者覆盖这些单元，但不要合并无关边界。一个狩猎者可以负责同一子系统内紧密相关的单元；不得因代理数量限制而让任何单元被静默地未分配——预算无法触达的单元应显式标记为 `deferred`，原因为 `budget_cannot_reserve_critics_and_validation`。

当预算或配置限制狩猎者数量时，按优先级顺序分配单元，并在台账中记录排序理由。排序依据：(1) 未认证或最低信任入口面优先于已认证入口面；(2) 保护最有价值资源的边界（凭据、跨租户数据、代码执行、发布权限）；(3) 前次运行的缺口、重新验证目标和已变更源码优先于同源重复检查；(4) 历史上对该目标类型能产出已确认发现的攻击类别优先于推测性类别。平局按 `coverage_id` 字典序打破，确保运行确定性。

启动前，父代理将已分配单元改为 `in_progress`，设置规范的小写 `agent_id`，并创建该代理的 `scratch/` 和父代理拥有的 `artifacts/`。狩猎者读取源码和父代理提供的上下文，只写入自己的唯一 `scratch/`，通过 Task 工具返回一个结构化结果。他们绝不写入保留产物，也不编辑目标源码、`architecture.md`、`coverage-ledger.json`、`findings.json` 或其他代理的文件。

## 必需的狩猎者提示词

每个狩猎者提示词按以下顺序包含这些部分：

1. 两句角色前言：狩猎者的目标是在其分配的单元中找到有源码依据的安全不变量失效，并且必须返回恰好一个 JSON 对象，匹配本提示词末尾的结构化结果契约。
2. 逐字复制 `architecture.md`。
3. 分配的覆盖率 ID、子系统、边界、仓库相对起始路径，以及每个单元在 `coverage-ledger.json` 中的分配块映射。
4. 逐字复制的确切选定块：从 `ATTACK-CLASSES.md` 中选定的每个普通攻击类别块，以及从每个选定伴随块中选取的 `Core discipline`、每个选定的攻击类别子节、`Universal moves` 和 `Validation rules`。普通块是自包含的，不携带伴随块风格的 `Core discipline`、`Universal moves` 或 `Validation rules` 节。不要只发送块名或伴随块名。
5. 显式排除的普通块和伴随块，并附上每个排除的理由。
6. 下面的核心狩猎方法，后接提升流程块。
7. 下面的核心验证规则。
8. 携带的同源先前已确认排除项，每项仅限指纹、标题和根因，加上此狩猎者不得重复的同伴拥有的当前覆盖率 ID。
9. 唯一的 scratch/产物路径、安全代理 ID、预先声明的提升允许列表和字节限制，以及结构化结果契约，包括下面的结构化狩猎者结果块和逐字复制的 `report-schema.json` 中 `confirmed` 与 `needs_validation` 分支。

当同一路径跨越多个领域时，提示词可以选择多个伴随块。保持它们的约束在一起。范围是狩猎者的覆盖义务，不是复制已排除工作的许可。如果出现意外的不同边界，将其作为 `uncovered` 返回，以便父代理创建稳定的台账单元并在下一波中分配。

#### 核心狩猎方法——包含在每个狩猎者提示词中

```text
## 防御性漏洞发现方法

你的目标是找到有源码依据的安全不变量失效及最小修复，
而不是将危害扩展到边界结果之外。保持在源码审查和有界本地执行范围内。
不要联系已部署的端点、提供商 API、镜像仓库、身份系统、
消息代理、共享服务或其他用户。仅使用本地虚拟数据。

深入阅读代码。追踪每个分配的输入经过解析、身份、
授权、规范化、状态、派生副本和最终汇点。阅读产生相同
效果的兄弟、遗留、批处理、重试、取消、迁移和错误路径。比较兄弟
控制是否等价，而不仅是是否存在，并比较一个组件保证的内容
与下一个组件假设的内容。

从具体不变量出发：
1. 命名较低信任主体和起始能力。
2. 命名被接受的值、动作、状态转换或资源选择器。
3. 定位应拒绝、绑定、隔离、限制或撤销它的控制。
4. 追踪该决策之后的精确源码路径。
5. 停在最小受影响虚拟记录、错误返回值、进程完整性
   影响或本地可观察的共享资源影响处。
6. 陈述强制该不变量的源码级变更和回归用例。

深度边界：只追踪能到达你分配边界或该边界所依赖保证的路径。
一旦不变量以任一方式确定，立即停止该调查线，并在结构化输出中记录结果——
covered、candidate 或 blocked 处置，或 `uncovered` 条目——而不是
继续搜索。

测试异常路径和分歧。仅在接口接受时检查缺失、空、零、负数、最大值、
超限、重复、混合编码、过期、已撤销、重排序、并发、
部分迁移、依赖失败和回滚状态。在每个解析器或策略交接处
比较规范化和单位。对于多步问题，将每个输出视为前提，不要假设后续
边界。如果任何前提未建立，记录阻塞项。

当提议的高危或严重候选揭示可复用的根因时，在分配的覆盖率 ID 拥有的路径中
搜索词法、结构和逻辑变体。合并相同根因，但独立建立每个变体的
条件和影响。不要调查同伴拥有的单元。将没有当前
覆盖率单元的变体作为 `uncovered` 返回。

使用能解决主张的最窄本地检查。目标控制的构建、
测试、进程、浏览器、模拟器、模糊器和夹具处理只能
在父代理批准的 OS 强制沙箱内运行。它必须禁用外部网络，
从空的允许列表环境启动，以只读方式暴露目标和工具，仅允许
写入你的 scratch 目录，并施加低 CPU、内存、进程、文件大小、
磁盘和墙钟时间限制。隔离回环仅允许用于本地夹具。
如果任何控制不可用，不要执行：返回 needs_validation 并附上该确切
阻塞项。优先使用现有单元测试、最小函数测试装置、虚拟租户服务
调用、小型畸形夹具、确定性竞态调度或本地渲染策略。
不要安装或获取工具。

记录确切输入、命令、限制和最小结果。对于环境，
仅记录复现检查所需的允许列表变量名和安全非秘密值。
绝不捕获环境变量、继承变量、凭据、
认证状态或无关主机路径。目标控制的进程只写入 scratch。在
沙箱及其所有进程终止后，只有受信任的父侧代码可以提升预先声明的
scratch 相对文件，遵循本提示词中逐字包含的提升流程块。你和目标代码绝不
写入保留产物。如果提升不可用或对决定性证据失败，
返回 needs_validation 并附上确切的提升阻塞项。
绝不压力测试可用性、调用实时目标、使用真实凭据、发布
产物，或越过最小观察效果继续。

源码之外的部署、浏览器、提供商、代理、OS、包、秘密或身份事实
不是任一方向的证明。如果某个此类事实是决定性的，返回
needs_validation 记录，附上确切缺失观察和安全的所有者观察检查。
```

#### 提升流程——将此提升流程逐字复制到每个狩猎者提示词中

```text
产物提升流程（仅受信任的父侧代码）：
仅供你参考：父代理执行这些步骤；你绝不执行它们。

执行前，父代理为代理的 scratch/ 和 artifacts/ 根打开并保留受信任的、
不可继承的目录描述符，并记录预期 scratch 相对产物文件的允许列表
以及显式的每文件和累计字节限制。绝不将这些描述符传递给代理或沙箱。
在沙箱及其所有进程终止后，受信任的父侧代码分别提升每个允许列表文件：

1. 验证声明的相对路径：拒绝绝对、空、`.`、`..` 或
   符号链接组件。
2. 从保留的 scratch 根描述符使用无跟随目录相对操作
   遍历每个父组件；绝不按路径重新打开。
3. 无跟随且非阻塞地打开叶子。
4. 用 `fstat` 验证它是常规文件，链接计数恰好为一，且在
   记录的每文件和累计字节限制内。
5. 从该描述符读取时再次强制执行这些限制。
6. 精确复制已验证的大小，重复 `fstat`，拒绝身份、类型、
   链接计数或大小发生变化。
7. 对于目标，从保留的 artifacts 根描述符使用无跟随目录相对操作
   遍历每个父组件；要求每个现有组件是真实目录，并以独占方式
   创建任何缺失目录，然后无跟随地重新打开并验证它。
8. 以独占方式创建叶子而不跟随链接，验证打开的目标是
   链接计数恰好为一的常规文件，并从已验证的源描述符复制
   而不重新打开任一路径。
9. 在非 POSIX 系统上使用等效的竞态安全 API。
10. 绝不递归复制或通配 scratch，将归档解压到 artifacts，或
    打开或提升符号链接、FIFO、套接字、设备、目录、硬链接文件、
    变化中的文件或超出其界限的文件。
11. 如果任何检查不可用、无法强制执行或失败，丢弃 scratch
    条目；如果它是决定性证据，保留 `needs_validation` 并附上确切的
    提升阻塞项。
```

#### 核心验证规则——包含在每个狩猎者提示词中

```text
## 候选门禁

1. 候选需要完整的仓库相对源码追踪和所声称根因的证据，
   包括最强的源码可见控制。
2. 提议的已确认记录需要有界本地观察结果、跨所述边界的有意义影响、
   完整条件，且无可见阻止层。
3. 不要将崩溃强化为代码执行，将普通工作强化为共享可用性，
   或将同主体动作强化为权限提升。
4. 如果所需事实不是源码可见或本地可观察的，使用
   needs_validation。命名确切阻塞项；不要赋予严重性或推测性完成。
5. 没有受影响主体/资源的最佳实践缺失应排除或归为加固，
   而非发现。被源码反驳的候选不是 needs_validation。
6. 在每个状态中对相同根因使用相同的源码派生指纹。
   它必须匹配 `^[A-Za-z0-9][A-Za-z0-9._:/@+-]*$`，且不得包含行、
   波次、代理、严重性或裁决。
7. 当没有候选通过这些门禁时，返回空候选数组。
```

## 本地验证边界

本地执行用于确认，而非影响扩展：

- **仅在必需的 OS 沙箱中允许：** 使用现有依赖的离线构建；使用虚拟状态的隔离回环进程；单元和集成测试；小型夹具处理；消毒器；有界模糊/回归测试；确定性并发检查；使用虚拟账户的本地浏览器/模拟器测试；使用虚拟身份的渲染清单和策略评估；模拟外部或付费调用。
- **禁止：** 实时或已部署流量；请求未为此隔离检查启动的服务；网络依赖安装；真实账户或凭据；生产数据；共享队列、云资源、运行器、镜像仓库、签名或发布服务；发布；压力测试、饱和或成本生成；在最小虚拟数据边界结果之后的任何工作。

沙箱以空环境启动，不给目标代码外部网络或主机可写路径，并对每个检查强制执行显式的低资源和时间限制，而不仅是预期昂贵的检查。Scratch 输出在退出后仍由目标控制。仅使用 `SKILL.md` 中的无跟随、路径限制、常规文件、有界大小主机流程提升它。缺少任何沙箱或提升能力不会抹除有源码依据的候选；在 `needs_validation` 中表示确切阻塞项。
