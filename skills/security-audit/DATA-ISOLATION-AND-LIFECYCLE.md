# 数据隔离与生命周期排查

#### 何时使用本文件

当目标存储多租户或受访问控制的数据、派生搜索/索引/缓存/分析副本、签发对象链接、导出或恢复记录、迁移 Schema，或承诺删除、撤销与保留行为时，使用本文件。本领域追踪单条数据在每份副本和每次状态转换中的流转。端点级访问控制见 `ATTACK-CLASSES.md`，提供商级存储策略见 `CLOUD-AND-DEPLOYMENT.md`。

大型目标按主存储、缓存/搜索、对象/Blob 存储、分析/日志、导出/备份、删除/撤销、迁移拆分。

## 核心准则（本领域每个 agent 提示词均须包含）

```
- 记录上的租户或所有者字段不等于隔离。为每条读写路径找到实际执行隔离的查询、键、路径、策略或行级控制。
- 追踪派生副本。已脱敏的主数据在搜索、缓存、分析、导出、预览、日志、副本和备份中可能因 ACL 与保留规则不同而变得不安全。
- 删除和撤销是生命周期契约。在产品声明的边界内检查当前、历史、缓存、索引、导出、恢复和队列中的副本。
- 隐私或保留偏好不自动构成安全漏洞。须有明确的数据访问边界或删除/撤销保证，以及未授权读取者或后续操作。
- 源码可见的完整链路和有界虚拟租户测试用 `confirmed`。外部存储策略、保留、CDN 行为、副本延迟或备份访问不可用时用 `needs_validation`。
```

## 租户与对象隔离攻击类（subagent_type: `general`）

**缺失租户或所有者强制**
读、更新、删除、列表、计数或批量查询在标识对象时未绑定已认证的租户/所有者，或信任请求体字段提供该身份。对比直接查找、嵌套关系、后台、管理、导入和遗留路径。

**复合键与命名空间冲突**
缓存键、对象路径、数据库唯一性、搜索文档 ID、临时文件或去重键遗漏租户或环境。两个主体可覆盖或检索同一逻辑键，即使应用记录带有各自的所有者。

**策略与查询不一致**
行级策略、ORM 默认作用域、授权过滤器和原始/绕过客户端应用不同谓词。检查连接、聚合、别名、视图、事务、`unscoped` 或服务客户端，以及上下文缺失的错误路径。

**Blob 与签名引用越权**
对象键、附件 ID、版本 ID、共享链接或签名 URL 允许超出签发主体权限的操作或命名空间，或在底层 ACL 变更后仍然有效。绑定操作、确切对象/版本、受众、过期时间和租户。

## 派生数据与泄露攻击类（subagent_type: `general`）

**搜索、缓存与索引 ACL 漂移**
主记录的 ACL 或生命周期变更后，未使可搜索、缓存、嵌入、缩略图、RSS、预览或索引副本失效。在检索时以及文档摄入和失效时均验证过滤。

**分析、日志、追踪与诊断作为替代读取者**
私有内容或凭据被写入访问范围更广、保留更久或租户混合的系统。确认数据类别和现实读取者；字段名、公开标识符和预期策略下的运维内容不足以构成发现。

**枚举与聚合预言机**
计数、过滤器、排序、错误、唯一约束、时序、通知行为或存在性检查泄露受保护对象或账户状态。须有具体的机密谓词和可观测差异，而非一般性响应差异。

## 导出、备份、恢复与迁移攻击类（subagent_type: `general`）

**导出与备份范围扩大**
导出、快照、可移植包、报告或备份包含其他租户、不可访问的对象字段、软删除数据、机密值或超出请求者权限的历史。在选择后逐项授权，并授权下载最终构建产物。

**导入与恢复权限扩大**
恢复/导入绕过所有者、Schema、ACL、唯一性或校验规则，覆盖现有资源，或在请求者无写权限的租户中重建记录。将归档内容视为不可信，授权结果操作而非信任先前来源。

**迁移默认值与所有权混淆**
旧记录缺少租户/ACL/生命周期字段，不兼容 ID 冲突，或部分上线使新旧读取者应用不同默认值。审查回填、双读/双写、兼容性、回滚和恢复迁移路径。

**备份与复制边界漂移**
加密密钥、存储账户、跨区域副本、恢复环境或支持快照的身份或租户范围比主数据更广。源码只能确认仓库内策略；托管访问和保留需 `needs_validation`。

## 删除、撤销与生命周期攻击类（subagent_type: `general`）

**软删除与墓碑绕过**
直接查找、搜索、关系遍历、对象链接、后台处理器或恢复忽略生命周期谓词，返回或操作已删除/撤销的记录。检查软删除标识符是否能在所有引用消失前重新注册。

**过期授权与派生副本使用**
成员移除、ACL 更新、同意撤回、机密撤销或角色降级未使会话、缓存、订阅、任务或物化数据失效，这些仍继续授权未来操作。

**保留与队列工作越界**
主存储中删除完成，但队列处理器、重试、导出、分析或生成的构建产物在承诺边界之外重建或保留数据。找到幂等删除和墓碑传播。

**恢复重新引入无效状态**
备份、撤销、取消删除或副本恢复还原了当前策略不再允许的数据、凭据、成员关系或权限。重新授权恢复状态并重新应用快照后的生命周期变更。

## 通用手法（适用于上述所有类别）

- 选一条受保护记录，画出主写入、查询、缓存、索引、事件、导出、备份、删除和恢复路径。在每条边上标注主体和租户。
- 通过相同本地服务方法对比两个虚拟租户，然后在 ACL 变更、删除、账户切换和恢复后重复。不要使用真实用户数据。
- 从绕过客户端、后台任务、迁移、全局唯一性和缓存键入手。这些路径常遗漏交互式端点携带的请求作用域身份。

## 验证规则（在此报告任何发现前适用）

1. 指明攻击者或低信任主体、受保护数据/状态、受影响所有者/租户、替代副本或操作，以及未授权泄露或变更。
2. 同时引用预期的真实来源策略和遗漏或不一致的那条路径。确认另一层未执行相同的租户/生命周期条件。
3. 使用本地虚拟租户和非敏感夹具证明跨范围访问或过期生命周期行为。在最小可观测记录或操作处停止。
4. 若需要外部缓存、对象存储、副本、分析、备份或保留策略，归类为 `needs_validation` 并说明所有者可观测的检查。
5. 仅在链路完整且边界影响具体时返回 `confirmed`。以确切未解决的存储、ACL、失效、保留或恢复事实返回 `needs_validation`。
