# 客户端与浏览器漏洞挖掘

#### 何时使用本文件

当浏览器中发生有意义的信任决策或不可信内容渲染时，使用本文件：单页应用、浏览器扩展、嵌入式 webview、Service Worker、离线应用，以及将攻击者可影响的内容渲染到 DOM、接收跨窗口消息或使用浏览器存储的代码。这些路径包含服务器永远看不到的来源，例如 URL 片段、`window.name`、`postMessage` 和先前缓存的内容。

配合 `ATTACK-CLASSES.md` 使用。本文件涵盖浏览器来源与汇聚点、源边界、浏览器持久化以及跨站状态预言机。webview 桥接的原生侧使用 `DESKTOP-MOBILE-AND-LOCAL-IPC.md`，服务端 CSRF、会话和认证回调使用 `WEB-PROTOCOL-AND-AUTH.md`。

## 核心纪律（本领域每个 agent 提示词都必须包含）

```
- 客户端候选漏洞需要一个可控来源和一个执行或泄露的汇聚点。两者都要指明，并展示攻击者影响的数据到达汇聚点。
- 影响必须触及受害者会话、另一个源或共享持久化。自我注入和泄露攻击者自己的数据不算发现。
- 框架转义、浏览器同源策略、CSP、COOP/CORP、Service Worker 作用域和现代 noopener 默认值是真实控制。分配影响前先验证它们。
- 浏览器存储和缓存按源共享，且可能比登录状态存活更久。识别谁写入、谁读取，以及哪个账户、租户或 worker 生命周期会清除每条记录。
- 仅在具备完整来源证据且有界本地浏览器测试时使用 `confirmed`。当需要渲染器、扩展权限、已部署响应头或浏览器策略行为但无法获取时，使用 `needs_validation`。
```

## DOM 与对象状态攻击类（subagent_type: `general`）

**基于 DOM 的 XSS**
追踪 `location` 字段、`document.referrer`、`window.name`、消息数据、存储和浏览器控制的文档状态流入 `innerHTML`、`outerHTML`、`document.write`、字符串求值 API、可执行 URL、jQuery HTML API 或框架逃逸口。框架已转义的插值不算发现。

**DOM clobbering**
攻击者注入的 `id` 或 `name` 属性遮蔽了代码后续信任的全局变量、表单属性、配置对象或初始化标志。需要同时具备保留该属性的标记路径和对被遮蔽值的安全相关使用。

**原型污染与利用链**
攻击者控制的键到达递归写入（如深度合并或路径赋值）并修改原型状态。然后一个可达的利用点消费被污染的属性，改变授权、执行、导航或渲染。仅有 `JSON.parse`、浅拷贝或无利用点的污染不够。

## 跨源消息与网络攻击类（subagent_type: `general`）

**`postMessage` 的源与来源信任**
处理程序使用 `event.data` 执行敏感操作，但没有精确的源允许列表，且在多个 frame 共享同一源时未校验预期的 `event.source`。发送侧，敏感数据发送到 `*` 会到达非预期的嵌入方。弱子串、前缀、后缀或无锚点正则的源匹配不是源校验。

**跨站 WebSocket 请求利用**
WebSocket 升级接受来自不可信源的 ambient cookie，没有 `Origin` 校验或通道专用令牌，使受害者会话能读取或修改数据。需同时确认升级行为和安全相关的消息处理程序。

**带凭据的 CORS 信任**
服务器在允许凭据的情况下反射或弱匹配 `Origin` 并返回敏感响应。带凭据的裸通配符会被浏览器拒绝；只报告实际反射/允许的源路径及跨源数据或修改。

## Service Worker 与浏览器存储攻击类（subagent_type: `general`）

**Service Worker 注册与作用域接管**
攻击者可影响的内容能成为注册的 worker 脚本、控制接收到过宽 `Service-Worker-Allowed` 作用域的路径，或在无完整性控制下修改更新导入。验证最终脚本 URL、响应 MIME 类型、源、作用域，以及谁控制每个导入的脚本。具有预期作用域的正常同源 worker 不是缺陷。

**Service Worker 缓存与身份混淆**
worker 缓存个性化响应时未将账户、租户、授权状态或请求模式纳入策略，然后在账户切换或登出后继续提供这些响应。审查 fetch 事件路由、缓存名称与键、导航回退、缓存清理，以及错误/离线路径是否返回另一用户先前的响应。

**浏览器存储泄露与过期授权**
令牌、私有响应、草稿数据或授权决策残留在 `localStorage`、`sessionStorage`、IndexedDB、Cache Storage、扩展存储或客户端状态中，并被另一账户或信任度较低的同源组件读取。仅存储令牌不算发现；需要存在权限更低的现实读取者，或在撤销/登出后仍继续使用。

**跨上下文存储与广播混淆**
`storage` 事件、`BroadcastChannel`、共享 worker 或源级缓存在标签页之间传递身份或命令，但未将其绑定到当前会话。检查账户切换、隐私/普通窗口、租户变更，以及可能覆盖较新认证状态的过期标签页。

## 跨站信息泄露攻击类（subagent_type: `general`）

**XS-Leaks 与跨源状态预言机**
攻击者页面能在浏览器附带受害者凭据的情况下，通过资源加载/错误事件、frame 或 window 状态、重定向行为、时序、缓存状态或响应大小区分受保护的跨源状态。需要一个具体的含密谓词，例如某个私有对象、角色或账户是否存在。通用时序差异或公共资源可用性不算发现。

**窗口与 opener 状态泄露**
跨源窗口被允许的元数据或导航结果泄露受保护状态，或保留的 opener/命名窗口关系让攻击者控制的页面影响特权导航。检查 COOP、frame 保护、`noopener`、精确源，以及可观察状态是否机密。

## UI 欺骗与导航攻击类（subagent_type: `general`）

**点击劫持**
被嵌入 frame 的状态变更操作缺少有效的 `frame-ancestors`、`X-Frame-Options` 或等效 UI 隔离。需要敏感操作并确认其能在被嵌入状态下完成；只读内容缺少响应头属于加固建议。

**客户端导航混淆**
客户端来源控制重定向或导航，但没有 scheme 和目的地策略，包括可执行的 `javascript:` 或 `data:` 目的地。反向标签页劫持仅适用于代码显式保留 `window.opener`、使用 `window.open` 且无隔离，或支持无隐式 `noopener` 的浏览器的情况。

## 通用方法（适用于以上所有类别）

- 从 DOM、导航、worker、消息和存储汇聚点出发，反向追踪到仅浏览器和服务器控制的来源。记录应阻断该路径的浏览器策略。
- 使用本地测试源和虚拟账户测试账户切换、登出、worker 更新、离线回退和过期标签页状态。不要使用生产用户、源或共享服务。
- 对于 XS-Leaks，只列出由源码和本地浏览器行为证明的谓词。然后识别能消除该预言机的响应头或渲染选择。

## 验证规则（在此报告任何发现之前应用）

1. 引用来源、汇聚点、浏览器策略、受影响的源/会话，以及可观察的修改或泄露。
2. 对于原型污染，证明递归写入和安全相关的利用点。对于 DOM clobbering，证明标记存活且被遮蔽的值被使用。
3. 对于 Service Worker 和存储，证明生命周期可达性：攻击者控制的写入或缓存条目必须到达不同账户、租户或后续授权状态。
4. 对于消息、CORS、WebSocket 和 XS-Leaks，展示精确的源/来源校验以及暴露的受保护状态或操作。确认 CSP、COOP/CORP、cookie 和 SameSite 策略未已阻断。
5. 仅在具备完整客户端路径和有界本地证据时返回 `confirmed` 发现。返回 `needs_validation` 时需附上所有者必须验证的精确已部署响应头、扩展权限、浏览器版本或渲染器行为。
