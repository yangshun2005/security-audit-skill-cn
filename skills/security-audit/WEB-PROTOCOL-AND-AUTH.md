# HTTP 协议与身份认证狩猎

#### 何时使用本文件

当目标在解析、缓存、浏览器认证或身份边界上使用 HTTP 时，使用本文件：Web 应用、API、反向代理、CDN、网关、自定义 HTTP 服务器，以及实现会话、JWT、OAuth/OIDC、SAML、密码找回、MFA、通行密钥、API 密钥或 mTLS 的服务。配合 `ATTACK-CLASSES.md` 使用：访问控制审查问的是某个主体能否执行某操作；本文件问的是 HTTP 层或身份层能否混淆该操作属于哪个主体、请求、保证级别或令牌。

从阶段 1 选取类别。将大型目标拆分为请求分帧与缓存策略、浏览器认证、联合身份、强认证与找回、服务凭据、会话生命周期。位于未观察到的托管代理之后的单一服务器，可源码确认的走私面很小；代理或自定义解析器则大得多。

## 核心纪律（本领域每个 agent 提示词中都要包含）

```
- 分帧与缓存发现需要对同一请求、响应或键的两种解读。指出两个组件及各自侧的确切规范化值。
- 对每个凭据，找到签名或密钥验证，以及其角色所需的每一项绑定：签发者、受众、源、RP、客户端、会话、主体、资源、保证级别、过期、一次性状态。
- Host、Forwarded、X-Forwarded-*、Origin、Referer、重定向目标、回调状态和请求派生 URL 都是信任决策。将每一项追踪到受影响的身份或响应。
- 缺失的头部、Cookie 属性、MFA 提示或速率限制本身不是发现。需要被接受的无效请求、跨主体影响、保证级别降级或凭据泄露。
- 仅凭完整源码证据和有界本地请求/令牌测试才归类为 `confirmed`。当需要代理、IdP、浏览器、证书、密钥或部署配置但不可见时，使用 `needs_validation`。
```

## HTTP 分帧与缓存攻击类别（subagent_type：`general`）

**请求分帧与去同步**
前端与后端对请求长度或头部规范化存在分歧。审查多个 `Content-Length` 值、`Transfer-Encoding`、HTTP/2 或 HTTP/3 降级、头部名称规范化、禁止的连接头部以及 CR/LF 转换。确认一个组件将哪些字节分配给一个请求，其对等方将哪些字节分配给下一个请求。

**通过未键控输入的 Web 缓存投毒**
请求值改变缓存内容或安全相关头部，但不在缓存键中。比较缓存键构造与每个响应变体，包括转发的 host/scheme、选定的 Cookie、查询规范化、语言/设备头部和授权状态。

**缓存欺骗与私有响应缓存**
缓存路由将私有动态路径视为公共静态资源，或缓存其身份和授权输入不在策略中的响应。比较边缘可缓存性与应用路由解析、后缀/路径参数规范化以及响应缓存指令。

**Host 与转发头部信任**
不可信的 host/代理元数据决定绝对 URL、租户路由、回调、重置链接、缓存键或授权使用的客户端地址。确认谁可以提供该头部，以及可信入口是否移除客户端提供的副本。

**响应头部注入**
不可信数据以不安全的控制字符或规范化到达 `Location`、`Set-Cookie`、CSP 或其他响应头部。报告前验证框架拒绝，并要求安全相关的响应变化。

## 浏览器会话攻击类别（subagent_type：`general`）

**普通 CSRF**
浏览器向状态变更端点发送环境凭据，该端点接受跨站请求，且没有有效的反 CSRF 令牌、同站请求绑定或严格的 Origin/Referer 验证。清点每个 Cookie 认证的变更操作，包括表单、类 JSON、multipart、方法覆盖和遗留路由。SameSite 仅对实际使用的 Cookie 和浏览器上下文有效；登录 CSRF 和跨站子资源请求可能有不同要求。

**会话固定与失效**
会话标识符在登录、账户切换、MFA 完成、模拟或其他权限变更时未轮换，或在登出、密码更改、撤销和账户禁用后仍然有效。检查服务器会话、刷新令牌、签名 Cookie、WebSocket 状态、缓存副本和回退端点。

**Cookie 作用域与传输**
敏感 Cookie 具有过宽的 `Domain` 或 `Path`，可跨越不安全传输，或与另一组件选择方式不同的同级 Cookie 冲突。仅缺失标志仍属加固说明，除非现实的较低信任源、网络位置或浏览器路径能获取或替换该凭据。

## 联合身份攻击类别（subagent_type：`general`）

首先确定角色。授权服务器控制（如重定向允许列表和代码签发）不属于依赖方客户端。验证和绑定缺陷属于消费该产物的组件。

**JWT 验证与声明绑定**
检查签名验证、服务器固定的算法和密钥来源，然后检查 `exp`、`nbf`、`aud` 和 `iss`。将 `kid`、`jku` 和 `x5u` 视为不可信密钥选择器，审查重复/头部规范化以及未验证解码路径。为另一服务签发的有效令牌在此无效，即使由可信签发者签名。

**OAuth/OIDC 请求与回调绑定**
当目标是授权服务器时，验证确切的 `redirect_uri` 所有权；会话绑定的 `state`；适用时的 PKCE 和授权码绑定；ID 令牌的签发者/受众/签名/nonce；以及多提供方流程中选定的 IdP 绑定。比较初始回调、重试、移动/深链接和账户关联路由。

**SAML 签名对象与断言绑定**
确保验证签名的元素就是用作身份的元素。审查未签名/回退路径、安全的 XML 解析器配置、规范化差异以及新鲜度/绑定字段，如有效期窗口、受众/接收方、请求关联和重放状态。

## MFA、通行密钥与账户转换攻击类别（subagent_type：`general`）

**MFA 注册与保证级别降级**
注册、替换、禁用、恢复码生成、可信设备创建和回退登录需要预期的先前保证级别。检查有效的第一因素是否能在没有策略要求的新鲜认证的情况下注册或替换第二因素，以及已禁用或过期的因素是否停止授权会话。

**步进绑定与绕过**
成功的挑战升级了错误的会话、账户、租户、操作或 API 请求，或替代路由省略了保证级别检查。将挑战绑定到主体、当前会话、保证级别目标、操作或资源（如需要）、过期和一次性完成。比较 UI、API、批量、找回和恢复流程路径。

**WebAuthn 与通行密钥验证**
注册时，将挑战、RP ID、预期源、凭据、用户/userHandle、算法和策略要求的用户验证绑定到发起会话。认证时，验证挑战、RP/源、凭据成员资格、签名和预期的用户存在/验证。检查账户发现和关联流程中的 userHandle 或凭据到账户的混淆。签名计数器处理仅在产品将回退视为克隆信号时才有意义。

**账户关联与身份冲突**
向现有账户添加 IdP、通行密钥、邮箱、电话、设备或外部账户必须要求当前已认证会话、新身份的所有权验证、策略要求的步进，以及绑定到发起关联账户的回调状态。审查取消关联/重新关联和邀请接受路径中的已验证标识符或租户冲突。

**密码重置与更广泛的找回**
找回令牌、支持/管理员找回、备份码、设备迁移以及邮箱或电话更改往往成为最弱的认证路径。验证令牌随机性、用户/操作绑定、过期、一次性状态、速率/计费控制、投递 URL 信任以及先前令牌和会话的失效。仅揭示公共账户存在性的不同响应不自动构成安全发现。

## API 密钥与 mTLS 攻击类别（subagent_type：`general`）

**API 密钥作用域与资源绑定**
密钥认证到比其服务器端记录授予的更广的租户、资源、操作或环境，或请求参数覆盖这些绑定。审查密钥查找、前缀/完整密钥验证、可发布密钥与秘密密钥之间的类型混淆、作用域检查、轮换、撤销缓存和批量端点。

**API 密钥暴露与不安全传输**
密钥出现在客户端包、URL、重定向、日志、错误路径、构建产物或较低信任主体可访问的响应中。称为密钥的公共标识符不是秘密。确认密钥类型及泄露所获得的权限。

**mTLS 对等方与应用身份混淆**
进程信任来自任何网络对等方的客户端证书身份头部，验证链但将攻击者可影响的主体文本错误映射到账户，或接受用于错误信任域、扩展用途、受众或有效性策略的证书。当可信代理终止 mTLS 时，仅验证该代理能连接、它移除传入身份头部，且后端将净化后的身份绑定到请求。

**证书生命周期回退**
过期、撤销、缺失或续期失败的证书导致静默回退到仅 bearer 或匿名操作，或长寿命池化连接在撤销后仍保留授权。缺失部署撤销数据使结果为 `needs_validation`；仓库内的 fail-open 分支可源码确认。

## 通用动作（适用于以上所有类别）

- 对每个凭据和挑战走查 签发 → 存储 → 传输 → 消费 → 刷新 → 撤销。比较正常、错误、重试、迁移、遗留和账户切换路径。
- 枚举通向同一身份的每扇门和通向同一敏感操作的每条路由。有效策略是最弱的并行路径，而非最精致的 UI。
- 并排对比解析器、代理、路由器、缓存和应用规范化。本地验证时，将相同的有限请求夹具输入每个组件，而非向实时部署发送流量。
- 对找回和关联，绘制账户前后图。每条边必须指明当前主体、新身份的证明、所需保证级别、回调/会话绑定和撤销效果。

## 验证规则（在此报告任何发现之前应用）

1. 应用源码可见性门。代理链、边缘缓存键、IdP 策略、证书信任、浏览器 Cookie 行为、密钥和部署的认证模式可能在仓库之外。记录精确的 `needs_validation` 候选，而非断言缺失的基础设施行为。
2. 对分帧和缓存发现，指出两个组件及分歧的解析/键。用有界本地夹具确认跨请求、跨用户或私有响应影响。
3. 对令牌、MFA、通行密钥、账户关联、找回、API 密钥和 mTLS 发现，引用验证行及缺失的主体/会话/资源/源/受众/操作/保证级别绑定。证明服务器接受无效转换或凭据。
4. 对 CSRF，指出环境凭据、状态变更路由、接受的跨站请求形态、浏览器 Cookie 策略和缺失的有效检查。只读操作和需要非环境 bearer 令牌的路由不符合条件。
5. 验证框架和库默认值。若版本或配置未知，使用 `needs_validation`；不要将未验证的关键声明转为较低严重性的已确认发现。
6. 仅凭完整源码追踪和可观察的未授权身份、状态或泄露返回 `confirmed`。对 `needs_validation`，指出缺失事实及解决它的安全本地或所有者观察检查。
